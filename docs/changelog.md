# 更新记录

## 0.3.4

- 新拉取到的模型自动获得可读显示名：新增 `src/model-name.ts` 纯本地归一化（品牌/缩略词大小写、版本号与日期折叠、尺寸后缀），与内置目录惯例一致（`gpt-7-sol` → `GPT-7 Sol`、`claude-3-5-sonnet-20241022` → `Claude 3.5 Sonnet 20241022`）。上游给出的真实名字优先；已知 ID 仍沿用目录取证名。归一化只是显示格式化，不产生任何能力、容量或权益证据。
- 选择模型不再被过期目录的全量刷新阻塞：`ensurePublished()` 在已绑定快照发布后立即返回（即使快照超过十分钟），`/models` 加逐模型预检的全量读取转后台执行；只有缺失或未绑定的快照才等待读取。新增回归测试证明选择路径在网关读取被挂起时仍能立即应答。
- 官网价格持久化并与拉取解耦：最后一次成功快照写入插件配置 `priceCache`，`status` 读取直接返回并标记为上次快照，插件重建后模型页不再空等抓取；超过七天或损坏的快照忽略。模型页首次打开仅在没有十分钟内新鲜快照时抓取，手动“更新价格”始终抓取；报价内容未变化不重写配置（时间戳最多每六小时刷新一次）。公开数据不按账号身份绑定。
- 配置写入持久化统一走 `_persistField`（仅版本冲突重试一次）；目录与价格快照写入不再轮换 status revision，也不参与登录指纹。
- 修复上下文按钮“经常变灰刷新”的直接耦合，改为中间件对接：新增 Host 侧 `src/selector-bridge.ts`，目录发布与任何 volatile 配置写入都经它按 `listModels` 可见投影（id/group/name/enabled/inputModalities）做差异比较，投影不变不通知选择器——保存档位、温度、协议、额度间隔等不再触发 Host 重建会话模型目录；替换同步执行并保留失败回滚与重试。新增客户端侧 `src/client-control-state.ts`，控件消费归一化控制状态而非 Host 目录原始 status：后台目录刷新不再置灰胶囊，仅待切换、目录错误、表单未就绪/只读、在途保存或缺容量参考才阻塞。
- 同类耦合排查结论：读取（`status`/容量缓存）与上游刷新解耦且经桥接差异发布；设置页控件只按表单就绪与在途保存锁定，不随目录状态置灰；写入统一经 `client-config-writes` 协调器；模型发现仍为 Host 驱动的有界实时询问。Loader 回归证明采样/档位写入不重发布选择器、启停写入仍重发布。

## 0.3.3

- 打开设置页不再显示“未知”并要求手动刷新：最后一次带数据的额度读数会持久化到插件配置（`quotaCache`），`status` 读取直接返回它并标记为“上次成功读数”及其更新时间；上游读取仍由自动/手动刷新单独触发。
- 读数按身份绑定：HMAC 覆盖网关、桌面登录态、已存 API Key 与控制台会话记录、环境 Cookie 引用；换账号、换网关或凭据轮换都不会复用旧数字，七天前的读数不再展示，绑定密钥不可用时既不保存也不恢复。
- 只保存带窗口或余额的读数，运行期簿记（下次刷新计划、失败计数、暂停状态、stale）不落盘；读数内容未变化时不重写配置（最多每 6 小时刷新一次时间戳），避免每次刷新都重建插件。
- 同一身份下刷新失败时保留已发布读数并标注“上次成功读数”，不会把已有数字替换成错误态。

## 0.3.2

- `deepseek-v4.1-flash-eco` 不再显示未知参数：Eco 就是 V4.1 Flash（操作者说明），两款共用同一份 1,000,000 窗口、384,000 输出、文本+图片输入与 none/low/high/max 思考档位（默认 high）。
- 网关报告的取整窗口不再顶掉精确参考：实测网关对 1,048,576 的型号报 1,048,000、对 262,144 的型号报 262,000。差值在 `min(1024, 参考的 1%)` 内的报告按同一窗口处理，保留 1,048,576 / 262,144 与二进制三档（262,144 / 524,288 / 1,048,576）；真正更小的报告仍然下调参考。
- 聊天侧上下文胶囊不再在挂载和每次模型目录刷新时各拉一次 `status`：容量行改为共享缓存（一次读取覆盖全部型号，五分钟窗口，单飞，读取失败保留旧值），控件不再因读取容量而禁用。这是切换窗口“最终能保存但很慢”的主要来源之一。
- 缓解设置写入后的刷新风暴：绑定同一身份的已保存模型目录会先直接发布（保留每条记录所在的通道，覆盖状态回到“未核实”），只有缺失、绑定不符或超过十分钟才做一次完整网关读取——此前每次插件重新加载都要为 46 个型号逐一预检。
- 同一 `index` 的工具调用分片若被网关改写了 ID，按同一调用处理并保留宿主已收到的第一个 ID，不再整轮失败（“本轮运行失败 OpenDesign：工具调用标识发生变化”）。缺少 ID 或名称仍然失败。

## 0.1.18

- 思考增量补读结构化的 `reasoning_details[].text`：网关把同一段思考写在 `reasoning` 与 `reasoning_details` 里时只取第一个有内容的拼写；此前漏读会让思考块打不开，推理模型的输出整段丢弃，最终表现为空响应。
- 目录快照保存只在版本冲突（`SETTINGS_CONFLICT`）时重试一次，其他写入失败立即报未保存：每次写入都会重写整份配置并可能重建插件树，重复一次注定失败的写入并不划算。
- 配置不再默认写入凭据引用名：DSH 模型页会读取配置里的引用名并当真，本机没有该引用时给两条通道打上“API 密钥缺失”，还把这两条通道当成待配置通道强制展开配置卡片。现在只有用户显式填写引用名才会写进配置，请求内部仍沿用 `COROUTER_API_KEY`：模型页不再报告这两条通道缺密钥。设置页的引用名输入框改为留空表示不命名（默认引用名只作占位提示），保存空值即清除已保存的引用名，避免顺手一存就把默认值固化成显式引用。模型页的就绪判定是全局合并的：只要这层不报缺失，页面就不再为任何通道弹出配置引导。
