# 连接与使用

## 推理连接

模型调用使用 CoRouter API Key 或设备授权取得的 runtimeKey；控制面的 controlKey 和旧控制台 Cookie 不能替代推理令牌。默认网关为 `https://amr-link.open-design.ai/v1`；在“高级”页直接选择 Chat Completions、Responses 或 Messages 协议，无需手填三套地址。具体模型的协议兼容性仍由服务端决定，见[协议说明](protocols.md)。

可选择：

- 在启动 DSH 的环境中提供 `COROUTER_API_KEY`，或沿用同名 DSH 凭据引用。配置里默认不写引用名（设置页的引用名留空即可），请求内部沿用 `COROUTER_API_KEY`；只有显式填写引用名后，DSH 模型页才会报告该引用名的密钥状态。
- 在设置的“连接与登录”页完成设备授权，自动保存控制面和推理令牌。
- 单独保存插件专属 API Key，覆盖设备授权的推理令牌。

连接页会显示当前生效的推理凭据来源。优先级为现有引用 / 环境 → 手动保存的 API Key → 设备授权 runtimeKey；若引用或环境已配置，保存新 Key 后仍继续使用该来源，页面会给出说明。设备推理令牌只用于官方 `https://amr-link.open-design.ai` origin，自定义网关需单独配置 Key，因此保存新 Key 不会覆盖共享引用。输入保存后清空，不回填。高级页提供协议、引用名、图片请求预算、请求超时、流空闲超时和额度自动刷新间隔。旧配置里的自定义基址继续生效；非回环地址要求 HTTPS，不允许 URL 内嵌凭据、查询参数或片段。

## 额度身份

读取顺序为桌面已有登录态 → 插件保存的设备授权（或旧版 Cookie 会话） → `OPEN_DESIGN_COOKIE` / `OPEN_DESIGN_SESSION` 引用或启动环境变量。关闭“优先使用桌面登录态”后，不读取桌面文件。

### 已有桌面端

默认只读生产 profile，配置目录沿用 `AMR_HOME`，未指定时是主目录下 `.amr`。控制面只信任 `https://amr-api.open-design.ai`，不会将非生产令牌改投生产。

桌面通道用钱包接口与 Vela 固定只读命令。Windows 默认检测官方安装位置；其他安装布局可通过绝对路径 `OPENDESIGN_VELA_PATH` 指定可信 Vela。插件不校验其签名，也不下载 CLI。

桌面认证失效时，会尝试独立会话；不拼接不同身份的额度。桌面接口权限较窄，某些分池可能未知，这是部分读取，不表示余额为零。

### 没有桌面端

1. 点击“开始设备授权”，取得授权码后插件自动尝试打开一次临时 Chrome 授权窗口。
2. 若窗口未打开，可点击“在新窗口打开授权页”重试，或点击“复制授权链接”并在常用浏览器粘贴打开。复制不可用时，选取页面给出的链接手动复制。
3. 核对授权码并在官方页面确认；返回设置页，等待显示授权已保存。设备授权同时取得 controlKey 与 runtimeKey，由 DSH 凭据服务原子保存到本插件的独立记录。

自动打开需要本机 Chrome。临时窗口使用独立会话，需要在其中登录；希望使用已有登录态时可复制链接到常用浏览器。打开操作最多等待约 20 秒，失败后可重试或手动打开。浏览器隔离和清理细节见[安全说明](../SECURITY.md)。

确认后自动保存授权。取消、超时或停用插件会结束等待并关闭插件打开的临时窗口；仅关闭窗口时，仍可在设置页取消登录。授权等待最多五分钟，服务端设备码可能更早到期。已保存的授权不会被随后到达的取消请求撤销。旧版 Cookie 会话继续兼容读取。

需要更多额度信息时，可先完成设备授权；接口权限不足时相应分池仍显示未知，不保证设备令牌与控制台 Cookie 权限相同。桌面结果不完整且独立会话能读到完整额度时，会整体使用独立会话并标明来源，不必再手工关闭桌面优先。额度身份未与推理 Key 的账号或工作区作一致性核验，请自行确认。

## 四层额度

| 显示 | 口径 |
| --- | --- |
| 套餐赠送窗口 | 服务端报告的各窗口用量 / 上限 / 剩余 / 重置时间 |
| 套餐余额 | `subscriptionCredits / creditsPerUsd` |
| 充值 / 赠送金额 | `rechargeCredits / creditsPerUsd` |
| 总额度 | 接口报告的钱包总余额或等价总额字段 |

赠送窗口显示周期用量，与钱包金额分别计量；总额度已包含各分池，缺失字段显示 `—`。窗口恢复、订阅账期结束与下次自动刷新分别标注。团队工作区仅展示相应工作区可读取的数据。自动刷新遵守缓存间隔；手动“刷新额度”立即重新取数，同时合并已有在途请求。读取失败按 5、10、20、40、60 秒退避，连续六次失败后暂停自动重试；手动刷新或修改额度来源可恢复。仍保留的旧读数会明确标记。

## 模型与空轮监控

点击“刷新模型目录”可读取当前网关的可用模型，使用该网关的 OpenAI 兼容 `GET /models` 接口，与推理协议选择独立。套餐赠送与付费模型分组展示；已知模型保留分组，新发现的对话模型进入付费组，实际计费由服务端决定。读取成功后会保存目录快照，宿主重启后继续使用，直到再次刷新；切换网关后旧快照不再生效。内置 ID 见 [模型表](../src/catalog.ts)。

网关明确报告的较小上下文窗口会在刷新后用于当前插件实例。它同时是可选窗口档位的上限：更小的网关窗口会让更高的档位不可选。手动保存的模型容量覆盖会保留，优先于发现值。目录快照写入失败时只提示未保存，本次运行仍使用新目录。

每行提供模型启用开关、图片输入开关、参数编辑和恢复默认。图片输入可手动启用或关闭，并可单独恢复目录自动判断；未知时会尝试发送图片，网关可能拒绝，见[图片能力证据](model-capabilities.md)。温度、top-p、默认最大输出、上下文窗口档位与默认思考深度保存到该模型的设置中；数值项空白表示继承。单次请求的温度和思考档位优先于模型默认值；输出长度仍受该模型配置的最大输出与剩余上下文约束。关闭模型后，它从宿主模型列表隐藏，直接调用也会被拒绝；已经准备好的请求保留原配置快照。

打开模型页时会读取官网公开参考价格，也可点击“更新价格”。模型行显示输入与输出单价，展开后可查看各输入长度分档及缓存读写单价；官网未列出的项目保持未知。价格来自官网而非当前网关，可能与账号实际计费不同，实际费用以账单为准。

上下文窗口按三个互斥档位设置：默认 272,000、扩展 500,000、最大 872,000，单位为 token。三档都是输入与输出**合计**的工作总窗口，不是留给输入的有效预算。有效窗口取所选档位与该模型已知参考中的较小值；超过已知参考的档位不可选，默认档按参考限幅。目录中的厂商参考值仍保留为容量参考，不会被改写成档位数值。

输出仍在这段窗口内预留。未显式设置最大输出时，自动预留最多为总窗口的 1/4，且不超过目录记录的单次输出上限；新默认下 DeepSeek V4.1 Flash 的有效总窗口为 272,000，自动输出预留 68,000，输入预算约 204,000。显式最大输出必须小于有效窗口；切到更小的窗口而与已保存的显式输出冲突时，保存被拒绝并提示先清除或调小输出，不会静默改写显式值。

旧配置中保存的任意上下文数值继续按原值生效：一律按自定义显示，即使数值与某个档位相同也不当作该档位，且不按已知参考限幅；模型行显示为自定义状态。只有选择档位才会替换它，选择默认档会清除该覆盖。「恢复默认」回到默认档，不会改用厂商参考的最大容量。

聊天窗口的模型选择框旁有一个上下文快捷按钮：只有当前会话选中的模型属于本插件的套餐赠送或付费通道时才出现，按钮上显示该模型当前生效的总窗口。点开是小弹层，列出默认 272,000 / 扩展 500,000 / 最大 872,000 三档，选中即保存。

这个按钮与设置页写的是同一份全局模型默认，不是会话级覆盖：使用同一模型的其他会话也会随之生效；已经准备好的请求继续使用原来的配置快照。切换模型会收起弹层，上一个模型尚未返回的保存结果不会写到新模型上。

两个入口共用同一个配置写入队列：配置修改逐个提交，同一字段保存期间两处均禁用；模型设置按字段差异合并到宿主当前值上，因此其他模型或同一模型的其他参数不会因这次修改而丢失。旧自定义数值、小容量限幅、显式最大输出冲突时保留原值，以及待保存与回滚的表现，两处完全一致。

容量设置是本地预算，不会扩大服务端限制，也不保证长输入、长任务在所有账号、协议与网关下都能完成。部分协议或模型不支持全部采样与思考参数，不兼容的明确设置会被拒绝，不会静默丢弃。

内联图片默认限制为每次请求 20 MiB，可在高级页调整。超过时插件请求宿主卸载较早的图片，宿主将这些图片在后续请求中替换为占位符，不删除原附件；摘要请求同样适用。网关返回 HTTP 413 且仍有图片时，插件请求进一步卸载并重试；没有可卸载图片时报告请求过大。自动处理依赖宿主的图片卸载插件，见[排障指南](troubleshooting.md)。

设置会自动保存：开关与协议选择立即提交，数值离开输入框时提交。页签下方显示保存结果；失败的开关恢复原值。加载中、配置不可用或只读时会说明原因。参数编辑区默认折叠，展开后查看能力信息与修改默认参数。

默认思考深度只列出当前模型和协议共有的档位。旧值标为“当前不可用”时，可选择有效档位或“继承默认”。固定思考、开关/预算型及未知型号不提供离散档位选择；来源与限制见[型号证据](reasoning-evidence.md)。

Claude 的原生 Messages 协议保留签名思考供后续工具调用使用；签名不作为可见思考文本展示。部分 Claude 型号在该协议下不能自定义温度或 Top P，旧值可在参数设置中清空。输入输出上限和其他协议的差异见[协议说明](protocols.md)。

“高级”中的异常结束监控仅控制本插件 Plan Provider 的 DeepSeek V4.1 Flash 工具对话，分为两层：空回答和已知协议残留归类为 `OPENDESIGN_EOT`，由默认开启的监控总开关控制；有正文的成功响应可在 Agent 结束前补充结构化收尾核验，该核验由“启用结束回合核验”单独控制，默认关闭。Paid Provider、其它 Provider 下的同名模型以及同 Provider 的其它模型都不受影响。流未到终态且工具调用尚未开始时归为 `TRANSPORT`，使用宿主原有重试策略。

`OPENDESIGN_EOT` 在 Agent 步骤内按退避间隔持续重试，无次数上限，可通过取消运行或关闭监控停止；认证、额度和其他错误仍由宿主策略处理。直接使用 `ctx.llm.stream()` 的调用不会经过 Agent 步骤恢复。重复请求可能额外消耗额度。

开启结束回合核验后，它通常增加一次模型步骤：模型确认已经完成、需要用户补充、等待后台工作、遇到阻塞或继续执行；本轮做过工具工作时，完成声明必须引用成功结果。默认最多追加 3 步，连续 2 次没有新成功工具结果时停止，可在高级页调整。原回答与工具结果保留，插件不重放工具或执行任意验收命令。已有未完成 Goal 时由原 Goal 机制控制；运行中的后台工作会进入等待。引用校验不等于独立证明全部要求已满足，详见[监控设计](empty-turn-evidence.md)。

设置中分别显示协议拦截、请求重试、结束核验和追加任务步骤的次数，以及最近决定、原因和时间。所有计数从插件加载起累计；“仅协议保护可用；收尾核验未启用”表示结束回合核验开关关闭或当前缺少收尾工具服务。取消、关闭监控、卸载以及一轮结束都会移除临时收尾工具。
